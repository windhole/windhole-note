# 0003. 10分ルールによるリビジョンの積み方

Date: 2026-08-29
Status: Accepted

## Context

エディタは自動保存(デバウンス 500ms 程度)なので、保存のたびにリビジョンを積むと履歴がキーストローク単位の細切れになり使い物にならない。かといって手動スナップショットは自分専用ツールでは絶対に押さなくなる。SPEC.md には「前回リビジョンから10分以上で積む / ページ離脱時にも積む / 直前リビジョンと同一内容なら積まない」という方式がすでに記されており、今回 `pages.ts` の実装にあたりこれを採用する。

## Decision

- リビジョンを積む判定は `pages.ts` の `save()` に集約する。ルートハンドラには書かない
- `save()` は毎回 `pages` を上書きし、その上で以下を満たすときだけ保存内容をリビジョンとして積む:
  - 内容(title, lines)が直前リビジョンと異なる、かつ
  - 「直前リビジョンが無い」「直前リビジョンの `saved_at` から10分以上経過」「離脱時保存(`leaving` フラグ)」のいずれか
- 復元は「現在の状態をリビジョンに積む → リビジョン内容で上書き」の順で行う
- 判定に使う現在時刻は引数 `now` で注入可能にする(テストで時計を進めるため)

## Consequences

- 編集セッション中は約10分おきのスナップショット+離脱時の最終形が残り、履歴一覧が人間に読める粒度になる
- 10分以内に書いて消した内容は履歴に残らない(離脱時保存で最終形だけは残る)。個人メモの用途では許容する
- 同一内容スキップの比較は `JSON.stringify(lines)` の文字列一致で行う。自前で常に同じ形でシリアライズするので誤判定はない
