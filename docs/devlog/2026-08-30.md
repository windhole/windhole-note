## SPEC.md 突き合わせレビューと取りこぼしの回収

### やったこと
- v1 が一通り揃ったので SPEC.md の全節を実装と突き合わせた。データモデル・API 10本・記法7種・機能一覧・`deleted_at` フィルタの網羅・「v1 で作らないもの」7項目(スコープクリープなし)はすべて実装どおりだった
- 見つかった取りこぼし3件を回収した
  1. **ADR-0004 起票 + SPEC.md 修正**: SPEC は `.devcontainer/` 前提だったが、実際は Claude Code on the web + `.claude/hooks/session-start.sh` で開発していた。実態を正として ADR を Proposed で起票し、SPEC の該当箇所を書き換えた
  2. **`scripts/update.sh` 追加**: SPEC 明記の2台運用スクリプト。`git pull --ff-only` → `bun install --frozen-lockfile` → typecheck → test
  3. **削除 UI 追加**: `DELETE /api/pages/:id` は実装済みだったがクライアントから呼ぶ導線が無く、アプリからページを消せなかった。PageView の nav に確認ダイアログ付きの削除ボタンを追加
- 削除の E2E: キャンセルで消えない / 承認で一覧から消えて `#/` に戻る / 削除済みページを直接開くとエラー表示 / 物理削除されておらず同名を開くと同じ行が蘇生し旧本文が履歴に残る

### 詰まった点・気づき
- レビューで残した「判断待ち」3件は今回手を付けていない: `#タグ` の表示で `#` が落ちる(挙動は SPEC どおりだが見た目が本家と違う)、`RelatedPages` が独立ファイルでなく PageView 内の `RefList`、履歴の「本文表示」が diff に統合されている。いずれも好みの範囲
- `update.sh` に typecheck と test を入れた。SPEC の記述は pull + install までだが、更新直後に壊れているより起動前に気づけるほうがよい
- 削除は論理削除で DB には残るが、UI からは戻す手段がない(復活は同名ページを開いたときの蘇生のみ)。そのため confirm を挟んだ
