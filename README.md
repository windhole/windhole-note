# windhole-note

自分専用のノートシステム。Scrapbox(Cosense)のローカル動作版のようなもの。

ページ同士を `[リンク]` でつなぎ、バックリンクと2ホップ先が各ページの下に並ぶ。データは SQLite ファイル1つとして手元に置き、マシン間で同期しない。

- 仕様の正本: [SPEC.md](SPEC.md)
- 設計判断の記録: [docs/adr/](docs/adr/)

## 必要なもの

[Bun](https://bun.sh/) だけ。

```sh
curl -fsSL https://bun.sh/install | bash
```

## セットアップ

```sh
git clone https://github.com/windhole/windhole-note.git
cd windhole-note
bun install
bun run dev
```

http://localhost:3000 を開く。

初回起動時に `data/pages.db` が作られ、マイグレーションが自動で流れる。以降の起動でも未適用のマイグレーションがあれば自動で適用される。

## 使い方

### 画面

| URL | 画面 |
|---|---|
| `#/` | ページ一覧(更新日時の新しい順)+ 検索 + 新規作成 |
| `#/p/<id>` | ページの表示・編集 |
| `#/p/<id>/history` | 履歴 |

### ページを作る

一覧のヘッダにタイトルを入れて「作成」。または本文中に `[まだ無いページ]` と書いてそのリンクをクリックすると、その場で作られる。

### 書く

本文は1つの textarea で編集する。**1行目がタイトル**。

編集中は 500ms ごとに自動保存される。保存ボタンは無い。「表示」に切り替えるか、一覧に戻るか、タブを閉じたときにも保存される。

### 記法

| 書き方 | 意味 |
|---|---|
| `[ページ名]` | ページへのリンク。存在しなければ開いたときに作られる |
| `#タグ` | `[タグ]` と同じ。表示は `#タグ` のまま |
| `[* 強調]` | 太字。`*` を増やすと大きくなる(`[** 中]` `[*** 大]`) |
| `[https://example.com]` | 外部リンク(別タブで開く) |
| `[/files/xxx.png]` `[https://.../a.jpg]` | 画像として表示(png / jpg / gif / webp / svg) |
| `code:ts` の次行以降でインデントした行 | コードブロック |
| 行頭のスペース / タブ | インデント(箇条書き相当) |

### 画像を貼る

編集中に画像をコピーして **Cmd+V**。アップロードされ、本文に `[/files/<ハッシュ>.png]` が挿し込まれる。ファイルは `data/images/` に内容のハッシュ名で置かれるので、同じ画像を何度貼っても1ファイルにまとまる。

### 検索

ヘッダの検索窓に入力すると、タイトルと本文を横断して候補が出る。3文字以上は全文検索インデックス、2文字以下は部分一致で引く。

### 履歴

ページの「履歴」から開く。左に版の一覧、右に選んだ版の中身。

- **差分** … その版に戻したら何が入り、何が消えるか
- **本文** … その版が当時どう見えていたか(記法を描画した形)
- **この版に戻す** … 現在の状態を履歴に退避してから、その版で上書きする

版は編集の10分ごと、およびページを離れたときに積まれる。直前の版と中身が同じなら積まれない。

### 削除

ページの「削除」。一覧と検索から消えるが、DB からは消えない(`deleted_at` を立てるだけ)。UI から戻す手段は無いが、同じタイトルのページを開き直すと空のページとして復活し、削除前の本文は履歴に残っている。

## データ

すべて `data/` の中にある。

```
data/
├── pages.db     # ページ・履歴・リンク・検索インデックス
└── images/      # 貼り付けた画像(最初の画像を貼ったときに作られる)
```

- `data/` は git に入らない。**マシンごとに独立**していて同期しない
- バックアップはこのディレクトリごとコピーすれば足りる
- 作り直したいときは `rm -rf data` して再起動

## 2台目のマシンに入れる / 更新する

コードは GitHub 経由で持っていく。データは持っていかない。

初回はセットアップの手順どおり。2回目以降の更新は:

```sh
./scripts/update.sh
```

`git pull --ff-only` → `bun install --frozen-lockfile` → 型チェック → テスト、まで流す。ローカルに未 push のコミットが残っていると pull が失敗するので、2台で別々に書き換えていたことにここで気づける。

## 開発

```sh
bun run dev        # 起動(ホットリロード)
bun test           # テスト
bun run typecheck  # 型チェック
```

スキーマを変えるときは `migrations/NNN_name.sql` を新しい番号で追加する。既存のファイルは書き換えない。詳しくは [CLAUDE.md](CLAUDE.md) を参照。

## 注意

- **認証は無い。** 誰でも読み書きできる前提の作り
- **`localhost` と表示されるが、実際は同じネットワークの他の端末からも届く。** 自宅なら手元の iPad から開けて便利だが、カフェや社内 LAN など不特定の相手がいるネットワークでは起動しっぱなしにしない。自分の端末だけに閉じたいときは `server.ts` の `Bun.serve` に `hostname: "127.0.0.1"` を足す
- HTTPS ではない。インターネットに公開する用途は想定していない
